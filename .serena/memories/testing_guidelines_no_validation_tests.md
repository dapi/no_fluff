# 🚫 Директива: Не тестировать валидации моделей

## Запрещено:
- ✗ Тестировать presence validations (username должен быть обязательным)
- ✗ Тестировать uniqueness validations (username должен быть уникальным)  
- ✗ Тестировать format validations (email должен быть валидным email)
- ✗ Тестировать length validations (имя не должно быть длиннее N символов)
- ✗ Тестировать числовые валидации (возраст должен быть > 0)
- ✗ Тестировать inclusion validations (статус должен быть из списка)
- ✗ Создавать Parameterized тесты для валидаций
- ✗ Использовать BaseModelTest (удален как плохая практика)

## Причина:
Валидации - это ответственность Rails framework и библиотек. 
Они уже хорошо протестированы и не требуют дублирования в проектных тестах.

## Что тестировать вместо этого:
- ✓ Бизнес-логика моделей
- ✓ Ассоциации и связи
- ✓ Scope и query методы
- ✓ Методы с кастомной логикой
- ✓ State machine переходы
- ✓ Callback логика
- ✓ Интеграционные сценарии

## Принцип:
Сосредоточиться на тестировании уникальной бизнес-логики приложения, а не на стандартном поведении фреймворка.
