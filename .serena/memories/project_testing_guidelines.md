# Руководство по написанию тестов для проекта NoFluff

## Обязательное изучение перед написанием тестов
Перед созданием любых тестов в проекте NoFluff необходимо изучить документацию:

**Основной документ**: `docs/Testing/testing-recommendations.md`

## Ключевые принципы тестирования в проекте:

### 1. Философия тестирования
- **RED-GREEN-REFACTOR**: Всегда пишем тесты перед реализацией
- **TDD подход**: Тесты первыми, затем код, затем рефакторинг
- **Изоляция**: Каждый тест независим и самодостаточен
- **Полнота покрытия**: Критические бизнес-пути должны быть протестированы

### 2. Специфика проекта NoFluff
- **Telegram Bot**: Использовать ClientStub, мокировать API calls
- **LLM сервисы (RubyLLM)**: Изолированные контексты, мокирование API
- **Concerns**: Sessionable, AdminAccess, Telegram commands
- **Фоновые задачи**: Bot join, deploy notifications, digest creation
- **Интеграции**: Полные user workflows от start до finish

### 3. Структура тестов
- Модели: валидации, ассоциации, бизнес-логика, enum, scopes
- Контроллеры: webhook processing, команды, callback queries
- Сервисы: бизнес-логика с моками внешних зависимостей
- Jobs: фоновые задачи с проверкой выполнения
- Интеграции: end-to-end пользовательские сценарии

### 4. Язык и стиль
- Имена тестов на русском языке, описательные
- Использование I18n.t для локализованных строк
- Фикстуры для базовых данных, создание в тестах для специфических
- Helper методы для повторяющихся действий

### 5. Анти-паттерны которых нужно избегать
- Глобальные переменные для хранения тестовых данных
- Сложные тесты с множественными условиями
- Игнорирование очистки после тестов (teardown)
- Отсутствие мокирования внешних API

## Памятка для агента:
1. **Прочитай** `docs/Testing/testing-recommendations.md`
2. **Изучи** существующие тесты в `test/`
3. **Применяй** паттерны из документации
4. **Следуй** RED-GREEN-REFACTOR подходу
5. **Используй** проектные фикстуры и helper методы

Это обеспечит консистентность и качество тестов в проекте.
