# 010_Special_Commands_for_Follower_User_Management_Specification

**Статус:** draft
**Дата создания:** 2025-01-02
**Автор:** NoFluff Bot Team
**Версия:** 1.0

## 1. Обзор и цели

### 1.1 Проблема
Для разработки и тестирования системы мониторинга Telegram-каналов необходим способ управления специальными пользователями (follower users), которые выполняют мониторинг каналов через специальные команды, недоступные обычным пользователям.

### 1.2 Решение
Создать систему специальных команд для управления follower users, позволяющую:
- Добавлять/удалять follower users в систему
- Просматривать список активных follower users

### 1.3 Цели
- Обеспечить администраторов базовыми инструментами для управления follower users
- Ограничить доступ к специальным командам только для авторизованных пользователей
- Предоставить минимально необходимый функционал для администрирования и тестирования: добавление, удаление, просмотр списка и авторизация follower users

## 2. Пользовательские истории

### 2.1 Основные пользовательские истории

**История 1: Добавление follower user**
- **Как:** администратор
- **Я хочу:** добавлять follower users в систему через специальную команду
- **Чтобы:** добавлять новые аккаунты для мониторинга каналов

**История 2: Управление списком follower users**
- **Как:** администратор
- **Я хочу:** просматривать список всех follower users и их статусы, включая авторизацию
- **Чтобы:** контролировать состояние аккаунтов мониторинга и их готовность к работе

**История 3: Удаление follower users**
- **Как:** администратор
- **Я хочу:** удалять неработающие или ненужные follower users
- **Чтобы:** удалять неиспользуемые аккаунты из системы

## 3. Требования

### 3.1 Функциональные требования

#### 3.1.1 Авторизация доступа
- **FR-1:** Только пользователи со специальным статусом `is_admin: true` могут использовать специальные команды
- **FR-2:** Система должна проверять права доступа перед выполнением команды
- **FR-3:** Неавторизованным пользователям должно отображаться сообщение об отказе в доступе

#### 3.1.2 Команды управления follower users
- **FR-4:** Команда `/fadd <phone_number>` - добавление follower user в систему
- **FR-5:** Команда `/fremove <phone_number>` - удаление follower user из системы
- **FR-6:** Команда `/flist` - отображение списка всех follower users с их информацией
- **FR-7:** Команда `/fconfirm <phone_number> <code>` - подтверждение авторизации follower user

#### 3.1.3 Валидация данных
- **FR-8:** Система должна валидировать формат номера телефона перед добавлением
- **FR-9:** Система должна нормализовать номер телефона к международному формату
- **FR-10:** Система должна проверять уникальность номера телефона

### 3.2 Нефункциональные требования

#### 3.2.1 Безопасность
- **NFR-1:** Все специальные команды должны логироваться
- **NFR-2:** Попытки несанкционированного доступа должны фиксироваться

#### 3.2.2 Производительность
- **NFR-3:** Команды должны выполняться не дольше 3 секунд
- **NFR-4:** Команда /flist должна отображать всех follower users без пагинации

#### 3.2.3 Usability
- **NFR-5:** Ошибки должны отображаться с понятными сообщениями
- **NFR-6:** Успешные операции должны подтверждаться сообщением

## 4. Спецификация команд

### 4.1 Формат команд
Все специальные команды начинаются с префикса `/f` (follower):

```
/f<command> [arguments...]
```

### 4.2 Описание команд

#### 4.2.1 `/fadd <phone_number>`
**Описание:** Добавление follower user в систему
**Аргументы:**
- `phone_number` - номер телефона пользователя

**Примеры:**
```
/fadd +79123456789
/fadd +79991234567
```

**Результат:**
```
✅ Follower user добавлен в систему
📱 Телефон: +79123456789
📋 Код подтверждения придет в Telegram

Используйте команду:
/fconfirm +79123456789 <код>
```

**Ошибки:**
```
❌ Ошибка: Неверный формат номера телефона
Используйте формат: +7XXXXXXXXXX

❌ Ошибка: Пользователь с таким номером уже существует
```

#### 4.2.2 `/fconfirm <phone_number> <code>`
**Описание:** Подтверждение авторизации follower user
**Аргументы:**
- `phone_number` - номер телефона пользователя
- `code` - код подтверждения из Telegram/TDLib

**Примеры:**
```
/fconfirm +79123456789 123456
/fconfirm +79991234567 654321
```

**Результат:**
```
✅ Follower user успешно авторизован!
📱 Телефон: +79123456789
📊 Статус: authorized
🏥 Готов к работе!
```

**Ошибки:**
```
❌ Ошибка: Неверный код подтверждения
Попробуйте снова или обратитесь к администратору

❌ Ошибка: Время на ввод кода истекло
Добавьте пользователя заново: /fadd +79123456789

❌ Ошибка: Пользователь с таким номером не найден
```

#### 4.2.3 `/fremove <phone_number>`
**Описание:** Удаление follower user из системы
**Аргументы:**
- `phone_number` - номер телефона пользователя

**Примеры:**
```
/fremove +79123456789
/fremove +79991234567
```

**Результат:**
```
✅ Follower user с телефоном +79123456789 удален из системы
```

**Ошибки:**
```
❌ Ошибка: Пользователь с таким номером не найден

❌ Ошибка: Нельзя удалить пользователя с активными каналами
Сначала отвяжите каналы или обратитесь к администратору
```

#### 4.2.4 `/flist`
**Описание:** Отображение списка всех follower users в системе
**Аргументы:**
- Нет

**Примеры:**
```
/flist
```

**Результат:**
```
📋 Follower users в системе:

1️⃣ 📱 +79123456789 | Статус: authorized
2️⃣ 📱 +79991234567 | Статус: pending
3️⃣ 📱 +79121234567 | Статус: failed
```

**Ошибки:**
```
❌ Ошибка: Follower users не найдены
```

## 5. Модель данных

### 5.1 Модель FollowerUser
```ruby
class FollowerUser < ApplicationRecord
  validates :phone_number, presence: true, uniqueness: true

  # Валидация формата номера телефона
  validates :phone_number, format: { with: /\A\+\d{10,15}\z/, message: "должен быть в международном формате" }

  enum auth_status: {
    pending: 0,    # Ожидает авторизации
    authorized: 1, # Авторизован
    failed: 2      # Ошибка авторизации
  }

  # TDLib данные для авторизации
  store :credentials, accessors: [ :phone_code_hash, :session_data ], coder: encrypt

  def authorized?
    auth_status == 'authorized'
  end

  def pending_authorization?
    auth_status == 'pending' && phone_code_hash.present?
  end
end
```

## 6. Архитектура

### 6.1 Контроллер
Команды управления follower users добавляются в существующий `Telegram::AdminCommands` concern, который подключается к `TelegramWebhookController`.

```ruby
# app/controllers/concerns/telegram/admin_commands.rb
module Telegram::AdminCommands
  extend ActiveSupport::Concern

  # fadd, fremove, flist, fconfirm методы добавляются сюда
  # existing channel commands remain unchanged

  private

  def check_admin_access
    unless current_user.is_admin?  # current_user всегда существует
      respond_with :message, text: '🚫 У вас нет доступа к этим командам'
      throw :abort
    end
  end
end
```
