# Спецификация 040: Обработка удаления бота из канала

## Обзор

Спецификация описывает функциональность для отслеживания и обработки ситуации, когда бот удаляется из канала Telegram.

## Проблема

Когда администратор удаляет бота из канала, система должна:
- Обновить статус присоединения бота к каналу
- Уведомить администратора об удалении
- Обеспечить корректную обработку последствий удаления

## Требования

### Функциональные требования

1. **Детекция удаления бота**
   - Система должна определять момент удаления бота из канала
   - При получении ошибки от Telegram API о том, что бот не является участником канала

2. **Обновление статуса**
   - Изменить статус join записи на соответствующий (например, "removed" или "left")
   - Зафиксировать дату и время удаления
   - Сохранить информацию о причине удаления

3. **Уведомление администратора**
   - Отправить уведомление администратору, который добавил бота
   - Включить в уведомление информацию о канале и времени удаления

### Нефункциональные требования

1. **Надежность**
   - Обработка должна быть устойчивой к временным сбоям API
   - Логирование всех операций детекции удаления

2. **Производительность**
   - Быстрая обработка событий удаления
   - Минимальная нагрузка на систему

## Модель данных

### Модификация существующей модели

**Join** (присоединение к каналу):
- `status`: string - текущий статус (active, left, kicked, removed)
- `left_at`: datetime - время удаления/выхода из канала
- `left_reason`: string - причина удаления (removed_by_admin, left_by_bot, api_error)

## Процесс обработки

1. **Детекция удаления**
   - При обращении к Telegram API получаем ошибку "bot is not a member"
   - Или при получении события о выходе бота из канала

2. **Валидация**
   - Проверяем, что бот действительно был добавлен в этот канал ранее
   - Убеждаемся, что статус еще не обновлен

3. **Обновление статуса**
   - `join.status = 'removed'`
   - `join.left_at = Time.current`
   - `join.left_reason = 'removed_by_admin'`

4. **Уведомление**
   - Найти администратора, который добавил бота
   - Отправить уведомление через Telegram

5. **Логирование**
   - Записать событие в лог
   - Зафиксировать метаданные для анализа

## Сценарии использования

### Основной сценарий
1. Администратор удаляет бота из канала через интерфейс Telegram
2. Система детектирует удаление при следующем обращении к API
3. Статус join обновляется на "removed"
4. Администратор получает уведомление об удалении

### Альтернативный сценарий
1. Бот покидает канал самостоятельно
2. Система детектирует выход через webhook
3. Статус join обновляется на "left"
4. Администратор получает уведомление о выходе бота

## Тестовые сценарии

1. **Детекция удаления через API ошибку**
2. **Обновление статуса в базе данных**
3. **Отправка уведомления администратору**
4. **Обработка повторной детекции удаления**
5. **Логирование события удаления**
6. **Работа с несуществующим join**
7. **Обработка временных сбоев API**

## Граничные случаи

1. **Несколько администраторов** - уведомить всех, кто имеет доступ
2. **Массовое удаление** - обработка удаления из множества каналов
3. **Ошибка при отправке уведомления** - повторная попытка через очередь
4. **Удаление после долгого отсутствия активности** - корректная обработка

## Интеграции

- **Telegram Bot API** - для детекции удаления
- **Система уведомлений** - для информирования администраторов
- **Background Jobs** - для асинхронной обработки
- **Bugsnag** - для отслеживания ошибок

## Ограничения

1. Задержка между реальным удалением и детекцией зависит от активности бота
2. Уведомления отправляются только пользователям с правами администрирования
3. История удаления не редактируется после создания

## Будущие улучшения

1. Webhook для мгновенной детекции удаления
2. Статистика по удалениям ботов из каналов
3. Возможность повторного добавления бота с сохранением истории
4. Анализ причин удаления для улучшения продукта
