# Спецификация 003: Подписка и бесплатный набор каналов

## Обзор

Спецификация описывает систему управления доступом пользователей к каналам мониторинга на основе подписной модели. Пользователям предоставляется бесплатный доступ к мониторингу до 10 каналов, с возможностью расширения через подписку.

## Требования

### 1. Бесплатный доступ

#### 1.1. Лимит бесплатных каналов
- Каждому пользователю предоставляется доступ к мониторингу **не более чем 10 каналов** бесплатно
- Лимит применяется только к **активным** каналам
- Неактивные подписки не учитываются при подсчете лимита

#### 1.2. Активация каналов
- Первые 10 добавленных каналов **автоматически активируются** для мониторинга
- Активация происходит независимо от статуса подписки пользователя
- Мониторинг начинается сразу после добавления канала

#### 1.3. Превышение лимита
- При попытке добавить 11-й канал пользователь получает уведомление о превышении лимита
- Пользователь не может добавить более 10 каналов без оформления подписки

### 2. Подписная модель

#### 2.1. Статус подписки
- Подписка определяет возможность добавления **более 10 каналов**
- Без подписки пользователь ограничен 10 активными каналами
- С подпиской нет ограничений на количество каналов

#### 2.2. Pilot режим
- В пилотном режиме подписка активируется через **клик на кнопку в боте**
- Кнопка предлагается когда пользователь достигает лимита в 10 каналов
- Процесс оформления подписки упрощен до минимума

#### 2.3. Премиум статус
- Пользователь с активной подпиской получает флаг `is_premium = true`
- Статус позволяет добавлять неограниченное количество каналов
- Существующие подписки пользователей сохраняются при изменении статуса

### 3. Поведение системы

#### 3.1. Добавление каналов
1. Пользователь добавляет канал через команду `/add @channelname`
2. Система проверяет количество активных подписок пользователя
3. Если активных подписок < 10 ИЛИ пользователь премиум:
   - Канал добавляется и **активируется**
   - Начинается мониторинг канала
4. Если активных подписок ≥ 10 И пользователь не премиум:
   - Предлагается оформить подписку
   - Канал не добавляется до оформления подписки

#### 3.2. Существующие подписки
- Все существующие активные подписки пользователей продолжают работать
- При изменении статуса пользователя на премиум сохраняются все текущие подписки
- Деактивация подписки не влияет на лимит (подсчитываются только активные)

#### 3.3. Мониторинг
- Мониторинг осуществляется только по **активным** каналам
- При добавлении канала он автоматически становится активным
- Система фоновых задач выбирает только активные каналы для мониторинга

## Технические детали

### 1. Модели данных

#### TelegramUser
- `is_premium` (boolean) - статус подписки пользователя
- Метод `active_channels_count` - количество активных подписок
- Метод `can_add_channel?` - проверка возможности добавления канала

#### Channel
- `active` (boolean) - статус активности канала для мониторинга
- По умолчанию `true` при создании

#### Subscription
- `active` (boolean) - статус активности подписки
- По умолчанию `true` при создании
- Scope `active` для выбора активных подписок

### 2. Бизнес-логика

#### ChannelService
- Константа `FREE_CHANNELS_LIMIT = 10`
- Метод `add_channel_for_user` включает проверку лимита
- При создании подписки устанавливать `active: true`

#### TelegramUser
```ruby
def can_add_channel?
  is_premium || active_channels_count < FREE_CHANNELS_LIMIT
end

def active_channels_count
  subscriptions.active.count
end
```

### 3. Пользовательский интерфейс

#### Сообщения об ошибках
- При превышении лимита: "Вы достигли лимита 10 бесплатных каналов. Для добавления большего количества каналов оформите подписку."
- При успешном добавлении: "Канал @channel добавлен. Всего каналов: X из 10"

#### Предложение подписки
- Кнопка "Оформить подписку" при достижении лимита
- Упрощенный процесс активации подписки в pilot режиме

## KPI и метрики

### 1. Метрики использования
- Количество пользователей с 1-10 каналами
- Количество пользователей с >10 каналами (премиум)
- Процент конверсии в подписку при достижении лимита

### 2. Метрики качества
- Время от добавления канала до начала мониторинга
- Количество активных vs неактивных подписок
- Успешность обработки подписок

## Риски и митигация

### 1. Риск: Неправильный подсчет лимита
**Митигация:** Использовать только активные подписки, добавить валидации в модели

### 2. Риск: Каналы неактивны по умолчанию
**Митигация:** Установить `active: true` по умолчанию и в логике создания

### 3. Риск: Потеря данных при изменении статуса
**Митигация:** Сохранять все подписки независимо от статуса пользователя
